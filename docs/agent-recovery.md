# Agent recovery

恢复必须保持三个边界：状态观察不启动执行，已接受的输入不由浏览器重发，原始 Product/Child Session journal 是唯一事实源。

父 Session 在子任务接受前追加 `session.child_tasks` 待处理关系。子 Session 保存接受回执与结果，父 Session 保存结果送达确认。只有结果已经确认、子任务没有活动运行或队列、交互及待处理后代时，才移除关系。最终检查、移除关系与关闭句柄共用子 Session 所属 Native Agent 的准入锁，直接 Queue/FollowUp 也不能越过退休边界；拒绝准入后的空日志清理使用同一锁，并以完整接受记录判断是否为空。结果送达使用完整的运行定位与父会话确认记录，不受界面最近 32 次运行窗口限制。暂停的后代继续参与恢复和树控制；已完成的历史子任务仍可通过精确身份查询。

正常 `/active` 查询沿待处理关系读取。Product Session 和 Native 子会话使用可重建的 `.idx.json.current` 观察索引，包含未完成状态、最后 32 个运行的定位信息和当前能力；完整历史定位保留在普通索引。观察句柄不获取执行所有权，也不能追加或修复原始 journal。缓存版本、校验或 journal incarnation 不匹配时，从原始日志重建。新 Session 在首个 Agent 事务中写入初始化标记，冷启动不会误走旧数据发现路径。最近 Release 的旧日志首次使用时只枚举一次目录，并追加待处理关系检查点；无需重写、双写或降级转换。

写作与通用会话的已对齐上下文检查点通过语义消息坐标读取保留区间。稀疏锚点保持 Context State 排序，跨锚点的外部工具开始记录通过原始定位读取，恢复后仍校验完整消息数和保留内容 hash。Clear 和历史修改会使旧检查点失效。游戏使用同一保留窗口接口。Story 索引保存祖先链、模型消息数量与原记录定位，按当前分支读取选中的 Turn、已吸收的延迟输入、未完成输入、正文修订和私有 provider continuation。分叉分支仍按原分支与读取边界隔离修订，重生成只读取目标父节点的前缀；消息投影复用同一编解码逻辑，最终仍验证原消息坐标、工具配对和内容 hash。

浏览器为状态读取和连接握手设置 15 秒基础设施超时；连接失败以随机退避重试，间隔最多 10 秒，连续 5 次失败后显示手动重试。每个 Session 只保留一个检查和一次显示连接，切换会话会取消请求并更新 generation，旧响应不能覆盖再次打开的同名 Session。重试只回送服务端投影的恢复身份，不重发缓存输入，不限制模型运行总时长。

状态观察成本取决于待处理子任务数量及各自的当前状态，不再随历史子任务目录大小反复扫描。执行冷恢复仍读取紧凑的历史回执与消息坐标元数据，历史正文只按保留窗口或精确查询读取；元数据大小仍随历史增长。Native file store 的执行恢复读取完整回执索引与提交尾部，观察恢复读取有界索引与尾部；两者都不重放已索引的历史正文。存储层通过通用 checkpoint reducer 接口复用生命周期投影，不依赖产品或 lifecycle 包。索引包含首尾事务校验与物理位置，每 256 条已提交记录及关闭时更新；缓存写入失败不改变已提交命令的成功结果。索引丢失、损坏、原日志 incarnation 变化、历史被修改或明确移除压缩时，从 canonical journal 重建。这里不承诺生产环境延迟，回归测试通过目录扫描次数、精确读取次数、缓存重建和原始日志不变性验证复杂度与正确性。

`TestStatusReadsOnlyPendingChildren` 使用真实 Product journal 和 Native file store，固定 2 个待处理 child，分别加入 20、300 个历史 child。每组 4 次查询（包含冷读取）均为 3 次精确读取、0 次目录扫描、0 次 writer 打开，也不会准备模型执行。另有回归覆盖首次升级只扫描一次、未送达结果超出最近运行窗口、空子任务接收新 Queue、损坏索引重建、保留上下文读取，以及浏览器超时重试与 A→B→A 的迟到响应。

状态观察和 journal 恢复失败或超过 1 秒时记录结构化日志。`[agent-recovery] status inspection` 给出会话、阶段、精确观察数量和耗时；`[conversation-journal] recovery` 给出观察/执行路径、锁等待耗时、缓存命中或重建、实际读取字节和事务数量。`[agent-session-file] recovery` 补充 Native 子会话的观察/执行路径、缓存命中或重建、原始 revision 和恢复耗时，缓存写入失败另有 warning。它们用于区分待处理树变大、缓存重建及磁盘/锁等待；这些日志不是完整的延迟分布或线上劣化统计。

新增回归验证 Native 索引命中时历史重放为 0、新提交尾部只重放 1 条记录、观察索引不保留历史正文、旧结果精确读取、缓存丢失与损坏重建。最近运行窗口按不同 Run 的最后一次结算排序，重复暂停不挤掉其他运行；取消队列后的观察不携带孤立历史控制记录，仍保留最新游标，执行恢复继续精确返回原始接受与取消回执。子任务退休和拒绝清理的并发测试确认新接受的 Queue 不会丢失，已关闭句柄不能重新注册关系。游戏窗口逐消息对比完整投影，覆盖分叉、修订、重生成、版本切换、延迟与未完成输入、重复工具 ID 和私有 provider continuation。Story 的千回合索引仍满足既有小于代表性日志 1% 的约束。
