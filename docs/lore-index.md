# 资料索引

资料库内的「资料索引」是一份连续的结构化文档。编辑区组织阅读指引、自定义分组和自动分组；宽屏右侧持续预览实际注入内容，窄屏可切换文档与预览。预览支持阅读视图、Markdown 源码、复制及估算 token 数，并随编辑自动更新。估算与上下文分析共用文本估算器，不代表模型实际计费量。

分组标题可直接拖动排序，自定义组和自动组可以交错排列；组内资料直接拖动卡片排序，不设拖拽把手。触屏长按拖动，键盘聚焦后按空格开始、方向键移动、空格或回车放下、Esc 取消。拖动不改变所属分组、启用状态或展示级别。排序自动保存到当前项目，编辑区、预览与写作／游戏实际上下文采用相同顺序。

没有排序设置时，自定义组按定义顺序在前，自动组按常驻及分类顺序排列，组内按名称排列。已排序的成员在前，新成员按名称追加；资料改名不改变已保存位置。暂时隐藏的自动组、禁用资料及解除关联的资料保留排序位置，再次出现时恢复；永久删除的身份在下次资料保存时清理排序引用。

## 分组决定直接注入的内容

每个分组统一选择名称、简介或全文。分组标题、导航说明、补充说明及相应粒度的成员直接出现在初始上下文。没有另外的「按需激活整个分组」开关，也不要求 Agent 先调用工具才能发现组内资料。

资料可以关联多个自定义分组，并继承组默认值或单独指定展示级别。多组关联取最完整的级别；完整内容只出现一次，其他位置留下名称引用。

关联资料支持按名称、关键词或标签搜索并多选，切换搜索保留勾选。一次提交所选资料；部分保存失败时保留失败项供重试，已成功项不重复提交。

未关联自定义分组的启用资料，按条目属性生成自动分组：

| 条目配置 | 自动分组 | 默认注入 |
| --- | --- | --- |
| 常驻 | 常驻 | 全文 |
| 角色 + 按需 | 角色 · 按需 | 名称 |
| 地点 + 按需 | 地点 · 按需 | 名称 |
| 角色 + 手动 | 角色 · 手动 | 名称 |
| 其他分类 + 按需／手动 | 对应分类与加载方式 | 名称 |

自动组的展示级别也可统一调整，并由后续新增、导入及重新归入的资料继承。只显示有启用成员的自动组。禁用资料不进入模型索引或查询结果。

**关联自定义组后，条目原加载方式仅保留为自动归组依据，自定义组及逐项设置决定当前注入。** 例如，常驻资料加入「名称」组后只注入名称；移出所有自定义组后，恢复「常驻」自动组的展示设置。自动组没有第二份成员列表。

## 存储和双向编辑

索引与资料共同保存在 `setting/lore/items.json`：

- `index_guide.intro_markdown`：阅读指引。
- `index_guide.groups`：有序自定义分组，包含稳定 ID、唯一名称、导航说明、Markdown 补充说明和默认展示级别。
- `index_guide.automatic_details`：自动组的展示覆盖值，例如 `resident`、`auto:character`、`manual:location`。没有覆盖值时使用上表默认值。
- `index_guide.group_order`：可选的统一分组顺序，使用 `custom:<分组 ID>` 或 `automatic:<自动组 key>`；未列出的组按默认顺序追加。
- `index_guide.item_order`：按上述分组 key 保存资料 ID 顺序，仅表示排序偏好，不决定成员关系。资源包导入导出通过原有 receipt 映射资料 ID，保留本地已保存顺序，并追加新的导入位置。
- `items[].index_memberships`：资料对自定义组的唯一关联来源，保存 `group_id` 及 `inherit`／`name`／`brief`／`full`。

索引页与单项「索引与加载」修改同一份关联。组改名不影响关系；删组前备份，只清除关联，资料继续保留并按剩余关系或自动分组加载；删除资料不需要同步删除索引名单。文档通过现有 revision、自动保存和冲突草稿恢复机制保存。资料集合资源包包含分组、自动组展示设置和成员关系，导入保留已有组及自动组的本地设置。

最近 Release 的资料无需手动整理或迁移到分组，保留原条目配置即可自动生成索引。内部 ID 只用于持久化、编辑器定位和关系维护，不进入注入的索引 Markdown。上一版未发布实现的分组激活开关不再使用。

## Agent 看到的 Markdown

```md
# Lore Index

## 港城人物

适合港口调查、税权冲突及商会交易场景。

- 港务署长 (Character / major / name)
- **盐商会长** (Character / important / brief): 掌握港城盐税与商船配额。

## Resident

### 潮汐法则 (Worldbuilding / important / full)

潮汐术只能转移已有水体，不能凭空造水。

## Character · On demand

- 温照野 (Character / major / name)
- 澜织 (Character / minor / name)
```

标题和用户说明保留原语言；系统引导及内置自动组标题使用英文。名称是可直接用于 Lore 工具的唯一名称。索引不包含 UUID、条目内部路径或存储 JSON。

条目首次展示时统一标明「分类显示名 / 重要度 / 实际展示级别」。级别按逐项覆盖和多组关联取最完整值之后的实际内容计算；全文为空时回退为简介并标明 `brief`，不会宣称正文已提供。全文不重复附带简介，后续同名引用不重复元数据。重要度表示叙事地位，不表示更高可信度或必须使用。标签不自动注入，仍可通过关键词检索并在工具结果中读取。预览、写作和游戏使用同一格式，不新增配置或存储字段。

`query_lore_items` 支持 `ids` 或 `names` 精确查询（不能与搜索条件混用），也可以搜索全部启用资料的名称、关键词、标签、简介和正文；可选 `group_names` 按索引标题查询自定义或自动组，并叠加关键词、分类和分页。分组查询只是额外的批量读取入口。工具返回沿用已有约定：默认及 `index` 返回简介，`full` 返回全文。分组注入设置不改变工具查询的返回粒度。精确查询同样默认返回简介，读取正文需显式指定 `detail=full`。查询结果包含 `material_count`、`cover_asset_id` 和 `next_offset`；缺失身份与后续分页分开报告。素材清单继续使用 `list_lore_materials`。

写作和游戏共用渲染逻辑；游戏的当前行动或计划资料引用也使用相同的全文判定来避免重复注入。修改未注入的资料正文不会单独改变初始索引前缀。

## 配置管理

写作和游戏的资料库配置管理共用 `config_read/config_apply`。`lore_index` 以 `index` 为固定 ID，读取并更新完整阅读指引、统一分组顺序、组内资料顺序、说明和默认展示级别，以及自动分组的展示覆盖值；`lore_index_membership` 按资料 ID 读取并单独更新关联和逐项展示级别。配置管理可以整理禁用资料的关联，但不会因此启用资料或把它们加入模型上下文。

修改沿用资料库的版本冲突校验和删组备份。批量归组逐项提交，只重试失败项；修改后重新读取核对。成员关系仍只保存在资料上，配置管理不会维护第二份名单。游戏游玩 Agent 仍只读，索引管理发生在配置管理会话中。

## 容量与预览

最多 256 个自定义组，标题最多 256 UTF-8 字节，导航说明最多 1024 字节，阅读指引最多 64 KiB。完整索引最多 1088 KiB；超限明确报错，不静默截断成员或正文。预览仍返回可编辑的自动组，让用户降低展示级别。Agent 的注入预算更低时，也会在模型调用前拒绝截断的上下文。

预览使用当前文档草稿与已保存资料，并与实际注入共用后端渲染器。正在更新时保留上一次结果并显示更新状态；无效输入或超限时显示错误，不把旧内容当作当前预览。
